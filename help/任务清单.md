# LPT v2 任务清单

## 文件定位

本文件是当前 v2-only 主线的任务清单。旧清单已从 `.tmp_lpt_v1_ds_archive/help/任务清单.md` 迁移到这里，并按 LPT v2 架构、checkpoint、状态池、训练入口和评测工具重新定义。

其他 Markdown 文件可以作为设计方案、实验报告、命令说明或背景材料，但不能自动改变本文件中的任务状态。任何任务完成度、优先级、成功标准或后续计划变更，都必须直接回写本文件。

状态标记约定：

- `[x]` 已完成，并已有代码或测试依据。
- `[ ]` 未完成或整体未完成。
- “部分完成”写在任务说明内，不用勾选代替。

## 迁移原则

- v2 主线只接受 `LPTV2`、`LayerStateV2`、`ModelConfig` schema v2、`checkpoint_format="lpt_v2_checkpoint"` 与 `architecture_version="lpt_v2"`。
- v1 checkpoint、旧 `ModelConfig`、旧训练 recipe、旧 LoRA、旧推理 session 和旧 checkpoint loader 不做兼容迁移。
- 旧任务若仍有价值，必须升级为 v2 任务：使用 `lpt_config/`、`lpt_model/`、`lpt_runtime/`、`lpt_data/`、`lpt_training/`、`lpt_workflows/`、`lpt_inference/`、`lpt_lora/`、`lpt_eval/` 和 `tools/` 下的正式模块。
- `.tmp_lpt_v1_ds_archive/` 只允许只读查阅，禁止作为运行时 import 依赖。
- 后续脚本与文档默认同时面向 Windows 10 / Windows Server 2019+ 和 Linux Ubuntu 22.04+ / CentOS 8+；路径处理优先使用 `pathlib.Path`。

## 当前工程基线

- v2 模型主干：`LPTV2`、`LPTBlockV2`、Local SDPA Attention、Paged KV、Shared RetNetAssist Q Adapter、SwiGLU-MoE、xLSTMAssist。
- v2 状态：`LayerStateV2`、RetNetAssist request-bound state pool、xLSTM request-bound state pool、Paged KV page pool。
- v2 配置：`ModelConfig` schema v2、多规格 preset、LongRoPE2 因子工具、MoE-aware 参数统计。
- v2 训练：`text_pretrain / chat_sft / chat_lora` 三阶段 workflow、正式训练循环、resume、optimizer/scheduler 状态、JSONL/TensorBoard 指标、周期性验证、LoRA adapter 保存。
- v2 数据：结构化 `text / chat` schema、manifest、流式加载、转换工具、sequence packing 和 token-based batching。
- v2 推理：`InferenceSession`、token-id 推理工具、checkpoint 摘要展示、推理执行计划。
- v2 评测：profile 基线、长上下文机制准入、资源报告、xLSTMAssist 专项评测。
- v2 治理：checkpoint schema v2 严格 loader、tokenizer metadata 随 trainer state 保存、v2 命令文档。

## 不变约束

- 禁止混用 v1 checkpoint、v1 tokenizer 元数据、v1 训练产物与 v2 模型。
- 后续训练、推理、评测、benchmark 和报告必须显式绑定 tokenizer 元数据。
- checkpoint loader 只接受当前 v2 schema；不为旧 `.pth` 或旧 schema 放宽校验。
- 模型结构必须通过 `ModelConfig` 或 checkpoint 内的完整 `model_config` 快照恢复。
- LongRoPE2 候选因子 sweep 只能临时覆盖评测进程内配置，不得写回 checkpoint 或训练产物。
- `CUDA_VISIBLE_DEVICES` 是单机多卡资源池边界；程序内部 device map 只使用 PyTorch 暴露后的逻辑设备号，例如 `cuda:0 / cuda:1`。
