# LPT v2 任务清单

## 文件定位

本文件是当前 v2-only 主线的任务清单。旧清单已从 `.tmp_lpt_v1_ds_archive/help/任务清单.md` 迁移到这里，并按 LPT v2 架构、checkpoint、状态池、训练入口和评测工具重新定义。

其他 Markdown 文件可以作为设计方案、实验报告、命令说明或背景材料，但不能自动改变本文件中的任务状态。任何任务完成度、优先级、成功标准或后续计划变更，都必须直接回写本文件。

状态标记约定：

- `[x]` 已完成，并已有代码或测试依据。
- `[ ]` 未完成或整体未完成。
- “部分完成”写在任务说明内，不用勾选代替。

## 迁移原则

- v2 主线只接受 `LPTV2`、`LayerStateV2`、当前 `ModelConfig` schema、`checkpoint_format="lpt_v2_checkpoint"` 与 `architecture_version="lpt_v2"`。
- v1 checkpoint、旧 `ModelConfig`、旧训练 recipe、旧 LoRA、旧推理 session 和旧 checkpoint loader 不做兼容迁移。
- 旧任务若仍有价值，必须升级为 v2 任务：使用 `lpt_config/`、`lpt_model/`、`lpt_runtime/`、`lpt_data/`、`lpt_training/`、`lpt_workflows/`、`lpt_inference/`、`lpt_lora/`、`lpt_eval/` 和 `tools/` 下的正式模块。
- `.tmp_lpt_v1_ds_archive/` 只允许只读查阅，禁止作为运行时 import 依赖。
- 后续脚本与文档默认同时面向 Windows 10 / Windows Server 2019+ 和 Linux Ubuntu 22.04+ / CentOS 8+；路径处理优先使用 `pathlib.Path`。

- v2 配置：`ModelConfig` schema v3、多规格 preset、LongRoPE2 因子工具、MoE-aware 参数统计。
- v2 训练：`text_pretrain / chat_sft / chat_lora` 三阶段 workflow、正式训练循环、resume、optimizer/scheduler 状态、manifest 数据进度账本、JSONL/TensorBoard 指标、周期性验证、LoRA adapter 保存。

- v2 评测：profile 基线、长上下文机制准入、资源报告、xLSTMAssist 专项评测。
- v2 治理：checkpoint schema v2 严格 loader、tokenizer metadata 随 trainer state 保存、v2 命令文档。

## 不变约束

- 禁止混用 v1 checkpoint、v1 tokenizer 元数据、v1 训练产物与 v2 模型。
- 后续训练、推理、评测、benchmark 和报告必须显式绑定 tokenizer 元数据。
- checkpoint loader 只接受当前 v2 schema；不为旧 `.pth` 或旧 schema 放宽校验。
- 模型结构必须通过 `ModelConfig` 或 checkpoint 内的完整 `model_config` 快照恢复。
- LongRoPE2 候选因子 sweep 只能临时覆盖评测进程内配置，不得写回 checkpoint 或训练产物。
- `CUDA_VISIBLE_DEVICES` 是单机多卡资源池边界；程序内部 device map 只使用 PyTorch 暴露后的逻辑设备号，例如 `cuda:0 / cuda:1`。

  - 数据结构：保留现有多轮 `messages` 能力，只扩展 assistant 消息字段，不改成单独顶层 assistant 对象。正式结构示例：

  ```json
  {
    "type": "chat",
    "messages": [
      {"role": "system", "content": "可选系统提示"},
      {"role": "user", "content": "用户问题"},
      {
        "role": "assistant",
        "thinking": "内部思考内容",
        "content": "最终回答"
      }
    ]
  }
  ```

  - 数据落位任务：`data/z-pending-data/thinking/` 只作为待处理源数据池；转换后进入 `data/structured/chat_sft/thinking/` 或 `data/structured/chat_lora/thinking/`，再由 manifest 引用。manifest 的 `weight / sample_limit / path` 等既有语义保持不变，`data_progress.json` 继续按文件粒度追踪。
  - 训练编码任务：训练 batch 增加原生 thinking 控制信息，例如 `thinking_mode_id`、`target_channel_id` 或等价结构；answer 与 thinking 目标需要可分离监督。`thinking=off` 的样本只监督最终回答；`thinking=on` 的样本监督 thinking 通道和最终回答通道。
  - 模型任务：在 `ModelConfig` 和 `LPTV2` 中增加原生 thinking 控制能力，例如 `thinking_mode` 枚举、mode embedding/control embedding 或等价条件信号；控制信号来自结构化 batch 与推理参数，不来自 prompt 文本。
  - 推理任务：推理入口支持 `thinking_mode=off|on|auto`。`off` 必须强制不生成 thinking；`on` 生成 thinking 与 answer；`auto` 由策略决定是否启用，但必须能被 `off` 覆盖。
  - 展示任务：将“是否生成 thinking”和“是否展示 thinking”拆开，增加 `thinking_visibility=hidden|visible` 或等价参数。`thinking=on` 且 visible 时返回结构化 `thinking` 字段；hidden 时只返回 answer，但不得把 thinking 混入 answer。
  - Checkpoint 与实验治理：checkpoint runtime metadata、trainer state、metrics 和实验报告记录 thinking schema 版本、训练阶段实际 thinking 样本统计、推理 thinking 参数与可见性参数，确保后续 checkpoint 可审计。
  - 测试任务：补 schema 测试、converter 测试、训练渲染/批处理测试、推理参数测试和无 `<think>` 回归测试。重点验证多轮 messages 不被破坏、非 assistant 禁止 `thinking`、`thinking=off` 不输出思考内容、旧 `<think>` 数据转换后正式样本不再含标签。

## P1.5：训练显存优化专项

- [ ] 7.3. 降低训练显存峰值并建立显存口径
  - 背景：当前训练显存主要由参数、梯度、优化器状态、反向激活、完整 `logits=[batch, seq, vocab]`、attention 中间张量、RoPE cache 和 PyTorch reserved cache 共同决定；`nvidia-smi` 口径会高于 `torch.cuda.max_memory_allocated()`，因此指标和优化必须分开治理。
  - 成功标准：训练日志同时记录 allocated/reserved 当前值与峰值；优化项通过 benchmark 对比 `sequence_length / target_tokens / tokens_per_sec / allocated_peak / reserved_peak / loss`；不使用每步 `torch.cuda.empty_cache()` 作为默认降显存手段。
  - 落地清单：
    - [ ] 1. 实现 `chunked lm_head + loss`：模型训练路径返回最后 hidden states，训练循环按 token chunk 调用 tied `lm_head` 并立即计算 CE，避免完整 `[B,S,V] logits` 常驻显存；未来 TP 场景下同步设计 vocab shard loss。
    - [ ] 2. 增加训练 `return_states=False`：训练 forward 不构造或返回推理用 `LayerStateV2`、RetNet/xLSTM detached state 和相关 dataclass；评测/推理保持原语义。
    - [ ] 3. 增加可开关 activation checkpointing：按 decoder block 或连续 block 分组重算激活，提供 `--activation-checkpointing` 与 checkpoint metadata 记录；默认关闭，长序列训练可开启。
    - [ ] 4. 优化 attention mask 与真实局部窗口执行：减少 dense mask 构造和长序列中间张量，评估局部 FlashAttention / block sparse / compressed sparse attention 作为后端候选。
    - [ ] 5. 调整 micro batch 与梯度累积策略：保持 `batch_size`、`gradient_accumulation_steps`、有效 token batch 的审计字段，确保小显存配置不改变 resume 和指标语义。
    - [ ] 6. 增加长度分桶与 packing 策略 benchmark：按样本长度分桶、减少 padding 与短长混批波动，报告 token 利用率、吞吐和显存峰值。
    - [ ] 7. 建立 LongRoPE2 长上下文课程：预训练默认优先使用 32K 级上下文形成稳定基座，后续通过窗口采样、LongRoPE2 因子和专项长上下文阶段扩展到 1M 目标；每个阶段绑定独立评测与 checkpoint 元数据。
    - [ ] 8. 收紧训练 RoPE cache 上限：`train_rope_cache_max_sequence_length` 不得大于本阶段实际训练窗口；窗口混合训练时评估按窗口重建/复用 cache 的显存收益。
    - [ ] 9. 完成 bf16/fp16 混合精度审计：CUDA 默认优先 bf16；记录参数 dtype、autocast dtype、loss 计算 dtype 和稳定性指标，避免静默退回 fp32。
    - [ ] 10. 引入 Muon 优化器候选：参考 DeepSeek-V4 对 Muon 的训练收敛和稳定性定位，新增 `optimizer=adamw|muon` 配置、参数组治理、`state_dict` / checkpoint 恢复、学习率与 weight decay 口径和回归 benchmark；Muon 作为 AdamW 的可选替代，不直接覆盖默认值。
    - [ ] 11. 评估 CPU optimizer offload：仅作为“训得起来优先”的低显存选项，明确标注吞吐损失；与 FSDP/ZeRO 路线解耦，不作为单卡默认路径。
